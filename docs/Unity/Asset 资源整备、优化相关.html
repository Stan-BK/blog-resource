资源是项目中不可或缺的一部分，Unity为引入项目的资源提供了定制化的功能，旨在为项目带来更好、更恰当的画面表现，也为了针对对于运行时、编译时的性能调优。

常见资源类型及优化手段

常见的资源类型有：

  • 纹理（Texture）
  • 网格（Mesh）
  • 材质（Material）
  • 模型（Model）
  • 音频（Audio）
  • 视频（Video）

以上资源都可以使用压缩（Compression）手段进行内存优化。另外有针对不同资源类型的优化手段：

  1. 纹理的优化
    • 纹理的适配是常常考虑的场景，处于动态场景（指代移动镜头观察下）的物体纹理，通常需要开启Mipmaps以适应不同分辨率下的展示，而在静态场景下，或是忽略Z轴移动的场景，则可以关闭生成Mipmaps（Generate Mipmaps）的选项。另外在无需运行时改动纹理资源的场景下，可以关闭Read/Write选项以告知Unity，避免运行时生成两份副本（分别存储于CPU与GPU），生成副本的原因是减少从GPU读取纹理资源的开销。
  2. 网格的优化

在无需运行时改动时关闭位于模型中Meshes的Read/Write项，可以有效减少内存开销。 在Mesh Renderer中，阴影投射以及光照探针等选项是默认开启的，在非必要时关闭也可以减少开销。

  1. 模型的优化

模型的优化囊括了网格的优化，除此之外还有操控架（英文名为Rig，应用于动画的角色框架）优化。无需动画表现时关闭Rig（于Rig菜单中设置Animation Type为None）可避免运行时自动生成动画组件计算的开销。 在开启了Rig项并设置其类型为humanoid时，可开启Optimize Game Objects选项以优化模型大小及烘培效率。

  1. 材质的优化

材质可勾选GPU Instancing以采用批处理手段优化Draw Call。

资源整备

资源工作流程

资源经由项目导入后，按项目规定的范式进行兼容，开发者可采取Unity内置的配置或自定义配置（AssetImporter）调整资源的表现形式，亦可通过脚本化控制、GUI配置管理等方式对资源的导入方式及流程进行控制；在构建阶段，资源会根据开发者指定形式进行归类打包，部分源构建环节可从项目构建环节分离开来（例如Addressables包管理配置为与程序分离打包）；最后依据不同资源包的不同性质，可采取各类发布以及分发手段提供给用户。

资源导入预处理/后处理

Unity提供了AssetPostProcesser对象来细度控制导入资源的流程环节。继承于AssetPostProcesser的类可以调用不同类型资源的预处理接口以提前整备资源导入Unity后使用的各项属性。 AssetPostProcesser支持资源的预处理以及后处理。 相关接口由OnPreProcess/OnPostProcess + <AssetType>定义，常用接口如下：

  • OnPreprocessTexture
  • OnPreprocessModel
  • OnPreprocessAnimation
  • OnPreprocessAudio

通过逆变实例对象属性assetImporter为ModelImporter类型后，即可在接口中实现资源的属性定制：

public class ReadOnlyModelPostprocessor : AssetPostprocessor {
   public void OnPreprocessModel() {
        ModelImporter modelImporter = (ModelImporter)assetImporter;
        if(modelImporter.isReadable) {
            modelImporter.isReadable = false;
            modelImporter.SaveAndReimport();
        }
    }
}

以上例子为导入的模型资源提前关闭 Read/Write选项。

资源并行导入

开启资源的并行导入，可以在批量导入资源时优化导入效率。更可设置同时处理导入的工作线程数以及最低期望工作线程数，降低Idle Import Worker Shutdown Delay（工作线程等待关闭时延）的时长可以加快切换加载工作线程的速度。

配置资源导入器

Unity除了提供的内置导入器外，还支持开发者自定义资源导入器以分析Unity资源分析名单外的资源文件。该自定义资源导入器由ScriptedImporter类支持，ScriptedImporter类与Unity内置导入器一样，继承于AssetImporter类。开发者可借助ScriptedImporter特性分析资源后缀，对特性定义的后缀文件进行导入监听，由ScriptedImporter类下的OnImportAsset方法获取到资源上下文，围绕资源进行Unity资产构建。

using UnityEngine;
using UnityEditor.AssetImporters;
using System.IO;

[ScriptedImporter(1, "cube")]
public class CubeImporter : ScriptedImporter
{
    public float m_Scale = 1;

    public override void OnImportAsset(AssetImportContext ctx)
    {
        var cube = GameObject.CreatePrimitive(PrimitiveType.Cube);
        var position = JsonUtility.FromJson<Vector3>(File.ReadAllText(ctx.assetPath));

        cube.transform.position = position;
        cube.transform.localScale = new Vector3(m_Scale, m_Scale, m_Scale);

        // 'cube' 是一个游戏对象，会自动转换为预制件
        //（只有 'Main Asset' 才能成为预制件。）
        ctx.AddObjectToAsset("main obj", cube);
        ctx.SetMainObject(cube);

        var material = new Material(Shader.Find("Standard"));
        material.color = Color.red;

        // 资源必须为资源分配一个唯一标识符字符串，且在所有导入之间保持一致
        ctx.AddObjectToAsset("my Material", material);

        // 必须销毁未作为导入输出传入上下文的资源
        var tempMesh = new Mesh();
        DestroyImmediate(tempMesh);
    }
}

其他细节

优化细节

  • 对于String类型的变量进行改动，性能开销和内存开销会因为String类型每次更新需要alloc新的内存空间而增大，在需要频繁更改的场景下，使用StringBuilder类型效果更佳。
  • 函数的调用是涉及到上下文切换、内存开辟等环节，无论函数内部实际执行语句量多少，以上环节都是必要的开销。所有因尽量避免多余的函数调用。
  • Vector、Quaternion类型计算的开销会比数值类计算的开销更大，在多种数值类型进行交互计算时，考虑交换律以优化计算的顺序，减少计算开销：
Vector3 x;

int a, b;

// 效率较低：产生两次矢量乘法

Vector3 slow = a * x * b;

// 效率较高：一次整数乘法、一次矢量乘法

Vector3 fast = a * b * x;
