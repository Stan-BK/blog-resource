前言

UI Toolkit作为Unity官方推出的新UI工具包，其不仅能提供运行时的UI界面绘制，还能提供Unity引擎的开发界面绘制。相较于IMGUI基于函数、UGUI基于场景的开发形式，UI Toolkit借鉴于H5的开发模式，对于熟悉H5前端开发的朋友来说更加友好，其借鉴了H5的开发流程：页面绘制（HTML-UXML、CSS-USS）、脚本交互控制（JS-C#）、布局系统（Flexbox布局），并延展出一套可视化生成工具，使开发能专注于UI呈现，而无需在意UXML代码结构。UI Toolkit在页面元素绘制上优于IMGUI，在事件绑定与Hierarchy--层级结构上优于UGUI，其功能模块的整合上则优于前两者。试想一下，在事件绑定、错误溯源时不用再困扰于组件的翻找（UGUI难处），在控件排布时不需要生敲代码（IMGUI痛点），更不用苦于编写数值驱动动画，UI Toolkit恰好带来了这些便利。

开发思路

确认开发模块性质

UI Toolkit覆盖了运行时、**编辑器（Editor Window）**的UI开发，前者为游戏内UI实现，后者为开发环境提供了自定义业务面板的能力。编辑器UI开发中还包含了两种开发切入方向： 第一种是完全自定义的业务面板开发，由 **Editor Window类 **提供了独立面板的开发接口，可实现诸如Hierarchy、Inspector等独立窗口的效果。 第二种为定制检查窗口（Inspector）中的展示细节，Unity使用C#特性的能力，为开发者指定的类型检查窗口进行定制，开发者可借助 **Editor类 **实现检查窗口整体或检查窗口内组件的UI界面。

初始化配置

运行时和编辑器的开发都遵循UXML的开发流程，必须具有uxml文件以作为页面渲染的控件记录文档，在其余的配置上，两者具有一定的差异性，以下是几个要点：

  1. 两者的控制脚本的父类不同

运行时UI的控制脚本需继承于MonoBeHaviour，对于控件元素类型、元素查找、事件绑定等属性或接口由命名空间UnityEngine.UIElements提供**。** 编辑器UI的控制脚本需分情况继承（参见开发思路 1. 确认开发模块性质）。

  1. 运行时UI需要有面板配置

在场景中使用UI Document时，UI Document组件需要引入UI模板（uxml）以及面板配置（PanelSettings)，该面板配置包含了UI Document作为场景UI元素的显示规则及排布规则。

  1. 编辑器UI开发脚本放置位置

推荐Editor相关的文件都放置于Editor文件夹下，遵循Unity的编译规则，易于引用管理和打包剔除等工作。

  1. 编辑器UI开发的UI Builder设置

Unity为编辑器UI提供了比运行时UI更多的控件，想要在UI Builder中使用这些控件，需要在uxml的文档配置中开启** Editor Extension Authoring** 选项。

组件化

对于需要重复渲染的页面元素，或是作为模块控件存在，支持复用到不同项目中的UI，都可以将其进行结构上的抽离，单独封装。这种旨在避免重复开发，优化渲染结构的做法名为组件化。 UI Toolkit支持组件化形式的开发，对于每一个UXML文档，都可以作为组件插入到主文档中，也可以从主文档中选定元素集合，进行抽离为UXML文档的操作。

需要注意的是，对于插入到主文档中的组件，会受主文档中存在的USS影响样式。

交互性

交互性的实现离不开事件驱动，UI Toolkit参照了H5的事件接口设计，提供了一套支持元素绑定的事件系统。
